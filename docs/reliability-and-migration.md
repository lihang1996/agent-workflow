# 协作流程恢复与配置迁移

## 工作流与职责

产品方案确认即流程终点，确认只保存记录，不自动交回 Leader 或派给开发。需要实现时由用户自行 @ 开发并附上文档。协作成员完成任务后直接通知用户。

运行时不再识别 `reviewBy` / `reviewMaxRounds`；旧配置中的字段会被忽略。开发内部根据工作区 `implement-ticket` Skill 调用 Tester 和 Code Reviewer，没有运行时固定的审查轮数。普通产品问答不会触发方案提交，只有实际调用 `request_spec_approval` 才生成确认卡。所有非 Leader 成员可以调用 `request_clarification`；只有 Leader 可以派发。

## 执行与交付

`src/index.ts` 负责装配。普通消息入口在 `src/app/message-handler.ts`，澄清和评论保留各自业务处理，但共用 `task-lifecycle.ts` 的会话占用、CLI 结果保存和运行释放。所有入口在成功、异常和取消后释放自己的运行记录；旧任务收尾不会释放另一个任务的控制器。

CLI 完成结果先保存到 `data/task-executions.json`，再生成交付内容。`data/result-deliveries.json` 保存卡片、长正文、提及和评论回复的补发记录与发送进度。暂时的发送失败会进行最多三次尝试；仍失败则保留记录，启动后及每分钟恢复。补发最多四路并发，不启动 CLI。提及通知等待对应结果卡成功送达；卡片持续失败会尝试发送备用文字说明。补发交互卡片时重新读取最新的流程状态，避免已回答或已确认的卡片被旧内容覆盖。

`/status` 展示最近执行状态和待补发记录数。`completed` 表示 CLI 已返回并保存结果，不等同于结果通知已经送达。结果处理或存储故障会明确报告，不能仅根据旧进度卡再次执行任务。

## 协作状态与重启

`data/collaboration-inbox.json` 记录协作状态及去重 ID。为兼容旧文件，记录数组仍使用 `pending` 字段名，数组内通过 `status` 区分阶段。

| 状态 | 含义 | 重启行为 |
| --- | --- | --- |
| pending | 等待派发或接收 | 用原 dispatchId 补发 |
| received | 会话已接收，正在准备卡片和附件 | 恢复为 pending，允许再次派发 |
| running | 已越过执行边界，CLI 可能已经产生副作用 | 标记 interrupted，不自动重跑 |
| completed | CLI 结果已返回 | 只补发已排队的结果 |
| failed | 执行失败 | 由用户检查后发起新的指令 |
| interrupted | 执行结果不确定 | 通知检查产物，不自动重跑 |

在进入 CLI 前持久化 running。若恰好在持久化与启动之间崩溃，也按结果不确定处理，宁可需要检查，也不重复可能有副作用的任务。原来只有 consumed ID、没有详细状态的历史任务继续维持去重，不推测执行结果。

发卡失败不会消费任务；目标忙碌时也不消费。重复投递不会再次启动已执行的协作任务。执行记录中的完成结果可以被同一澄清或评论重试复用，后处理失败不会重复修改文件或文档。

## 会话版本与身份

会话新增 `version` 和 `owner`，澄清与方案记录新增 `sessionVersion`。旧数据缺少版本时按 0 读取，无需手动编辑状态文件。`/new`、工作目录变更和历史会话选择会增加版本；普通 CLI 续跑保存原生会话 ID 不增加版本。

旧流程与当前会话版本不一致时，澄清、方案确认及评论修改均被拒绝。历史记录可以继续保留，版本不匹配的 pending 记录在运行时已失效，不能继续操作新上下文。已经确认的方案记录不撤销。

`/close`、`/new`、`/cd <目录>`、`/resume`、`/compact` 以及历史会话选择共用所有者校验。普通任务消息也不能接管其他用户的已有会话。任务身份优先比较同一开发商范围内的 union_id；缺少 union_id 时，只在原应用内比较 open_id。没有 owner 的旧会话在下一次任务开始时建立归属；旧待处理流程仍使用其中已保存的所有者。

评论只有原发起人能够请求修改。排队或执行评论期间不能确认，确认后不能继续评论修改。执行前再次检查方案状态与会话版本。

## 保留范围与部署

只支持单进程独占 data 目录。升级前备份该目录；新旧版本不要同时操作同一份状态文件。

- 协作执行的终态详细记录保留最近约 1000 条，消费 ID 保留最近 10000 条。未处理与结果不确定记录不会自动丢弃；积压达到 1000 条时拒绝新增协作任务。
- CLI 执行结果及已送达通知各保留最近约 1000 条；未送达通知和结果不确定的执行记录不自动清除。
- 产品终态历史保留最近约 1000 条，等待确认的记录保留。旧版本流程由会话版本校验阻止执行。
- 去重保证受历史保留范围限制。消息 UUID 用于减少重复发送；评论回复不具备相同的幂等参数，网络结果不确定时可能重复回复，但保留的执行记录阻止重复执行 CLI。

## 飞书评论与 Windows

产品通常通过用户身份创建文档，Bot 使用应用身份订阅和回复评论，需要对应事件权限和文档访问权限。订阅失败只降级评论监听；修复权限后重启。Wiki 链接先解析为 Docx，无法读取则明确报错。

Windows 原生 exe 直接启动，标准 npm cmd 启动器解析到 Node 入口，参数不经过 shell。未知自定义批处理被拒绝。工作区产物继续检查 Windows 绝对路径、穿越及符号链接逃逸。
