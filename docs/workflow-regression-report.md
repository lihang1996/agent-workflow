# 工作流修复与复测记录

复测日期：2026-09-10。改动保留在当前工作区，未创建 Git 提交。

## 修复项

| 审查问题 | 处理结果 |
| --- | --- |
| 确认后交接失败无法重试 | 确认状态与交接完成状态分开持久化；固定 dispatchId；失败可再次点击，启动和定时恢复也会重试 |
| 澄清发卡失败卡住会话 | 从初始化开始统一执行 finally 清理；保留已选答案，并显示重新整理按钮 |
| 跨 Bot 停止失败 | 保存 ownerUnionId 和 ownerBotId；跨应用优先比较 Union ID，不跨应用比较 Open ID |
| 普通产品问答被强制提交 | 没有真实提交工具调用时按普通回答结束，不重跑 CLI，不使旧方案过期 |
| 评论订阅阻断启动 | 订阅失败降级并记录权限诊断信息，其他 Bot 不受影响 |
| 澄清状态重启丢失 | 原子持久化问题、答案、当前题目、所有者和协作来源 |
| 直接咨询的确认文案错误 | 直接咨询明确只保存确认记录；协作方案区分交接待重试与已交接 |
| 评论修改缺少所有者校验 | 仅原任务发起人可以触发评论修改，排队前及实际执行前校验 |
| 普通话题消息绕过澄清归属 | 消息入口复用所有者校验，后续流程沿用原 owner 身份 |
| 确认与评论修改并发 | 排队即占用修改名额，确认等待队列清空；执行前重新检查方案状态 |
| URL 校验宽松、Wiki 不支持 | 校验 HTTPS、官方域名、精确路径；Wiki 经 SDK 解析到 Docx token |
| 本地路径边界不足 | 校验 Windows 绝对路径、穿越与实际 realpath，拒绝符号链接越界 |
| reviewBy 自动审查 | 已按后续要求恢复为内置独立 CLI 审查；通过直接结束，有问题修复复审，默认最多 3 轮，不交回 CEO |
| 长文本二次截断 | 统一 3000 字符限制，按 Unicode 字符分段，保留空白与完整正文 |
| 集合及历史无限增长 | 协作去重和终态历史有保留上限，未完成交接不清除 |
| 协作 inbox 重启丢失 | 持久化待派发和消费记录；目标忙碌时不提前消费；恢复使用原 dispatchId |
| Windows shell 转义 | 直接启动原生程序或 npm shim 的 Node 入口，参数不经过 shell |
| IDE/缓存/一次性草稿混入提交 | 加入忽略规则，保留现有本地文件 |
